# ชุดทดสอบ — สมุดบันทึกการเทรด

ทดสอบ `index.html` / `sw.js` ของโปรเจกต์นี้ (ไม่ได้ถูกใช้ตอนรันแอป — อยู่ใน repo เพื่อให้รันซ้ำได้)

## เตรียมเครื่อง
- Python 3.10+ และ Node.js (สำหรับตัวเทียบตัวคำนวณ)
- `pip install playwright` แล้ว `python -m playwright install chromium webkit`

## รัน
```
cd tests
python run_all.py                       # ครบทุกชุด (Chromium)
python run_all.py --browser webkit      # ชุด UI/SW บน WebKit (ยังไม่ใช่ Safari บน iPad จริง)
python run_all.py --quick               # ชุดข้อมูลสุ่มน้อยลง ใช้ระหว่างพัฒนา
python test_tj4.py                      # รันทีละไฟล์ก็ได้ (BROWSER=webkit ได้)
```

## แต่ละไฟล์ทำอะไร
| ไฟล์ | ครอบคลุม |
|---|---|
| `test_tj.py` | ซื้อ-ขายวันเดียวกัน, สำรองข้อมูล/เตือน, แท็ก-โน้ต-อารมณ์, ปันผล, สถิติ, ค่าธรรมเนียมอัตโนมัติ, นำเข้าไฟล์เก่า |
| `test_tj2.py` | บันทึกอารมณ์ (ลบ/แก้ไข), ส่งออก CSV, เลย์เอาต์ |
| `test_tj3.py` | แก้ข้อค้นพบรีวิวรอบแรก: ลำดับขาย→ซื้อกลับ, แท็กชื่อพิเศษ, ค่าติดลบ, นำเข้าไฟล์เสีย, แก้ค่าธรรมเนียมตอนแก้ไขรายการ |
| `test_tj4.py` | หลายแท็บ, นำเข้าแบบทั้งหมดหรือไม่เลย (โควตาเต็ม), ตัวตรวจข้อมูล, ข้อมูลในที่เก็บเสีย, วันที่เริ่มต้น |
| `test_tj5.py` | ปุ่มเลิกทำ (ลบ/นำเข้า), อายุแถบ, คืนตำแหน่ง |
| `test_tj6.py` | รอบรีวิวที่ 3: รุ่นข้อมูล (epoch), merge ตอนแก้รายการพร้อมกัน, ภาษีปันผล, วันที่อารมณ์ |
| `test_sw.py` | service worker บนเซิร์ฟเวอร์ทดสอบจริง: แคช, ออฟไลน์ (ตัดการเชื่อมต่อที่ฝั่งเซิร์ฟเวอร์), 503/redirect, โดเมนอื่น |
| `test_diff.py` + `diff_node.js` | **ตัวเลขเงิน**: ดึง `computeLedger`/`computeStats` จาก index.html ไปรันใน Node เทียบกับตัวอ้างอิง Python เลขเศษส่วนแม่นยำ + กฎคงตัว (ต้นทุน/จำนวนรวมคงที่, กำไรลบต้นทุนคงเหลือเท่ากันทั้ง FIFO/AVG) |
| `test_diff_ui.py` | เทียบตัวเลขที่ "แสดงบนหน้าจอ" (การ์ดสรุป ตาราง) กับตัวอ้างอิงเดียวกัน |
| `mutation_check.py` | ใส่บั๊กลงสำเนา 7 แบบ แล้วดูว่า `test_diff.py` จับได้ทุกแบบ (พิสูจน์ว่าตัวเทียบไม่หลวม) |

ตัวแปรสภาพแวดล้อม: `BROWSER` (chromium/webkit), `N` และ `SEED` (จำนวน/เมล็ดสุ่มของ `test_diff.py`), `HTML_OVERRIDE` (ทดสอบกับสำเนา index.html อื่น)

## กติกา
- **แก้สูตรคำนวณเมื่อไหร่ ต้องรัน `python run_all.py` (เต็ม) ให้ผ่านก่อน push** — โดยเฉพาะ `test_diff.py` และ `mutation_check.py`
- ถ้าแก้โค้ดจน `mutation_check.py` ขึ้น "anchor missing" ให้ปรับรายการบั๊กจำลองให้ตรงโค้ดปัจจุบัน (อย่าลบทิ้ง)
- ไฟล์ชั่วคราวเขียนที่ `%TEMP%\tj-tests` ไม่แตะไฟล์ใน repo

## ข้อจำกัดที่รู้
- UI ทดสอบผ่าน `file://` (ง่าย/เร็ว) — WebKit ไม่ส่งเหตุการณ์ `storage` ข้ามแท็บให้หน้า `file://` (ผ่าน http ส่งปกติ) ชุดทดสอบจึงปลุกแท็บเองเพื่อทดสอบกลไกสำรองของแอป
- ออฟไลน์ของ service worker จำลองด้วยการตัดการเชื่อมต่อที่ฝั่งเซิร์ฟเวอร์ ไม่ใช้ `set_offline` ของ Playwright (บน WebKit ทำให้หน้าที่ SW ตอบจากแคชล้มด้วย)
- WebKit ของ Playwright บน Windows ไม่เท่ากับ Safari บน iPad — ต้องลองบนเครื่องจริงเสมอ
- ผลเทียบตัวคำนวณพิสูจน์ว่าตรง "สูตรที่ตั้งใจ" ไม่ได้พิสูจน์ว่าตรงใบยืนยันของโบรกเกอร์
